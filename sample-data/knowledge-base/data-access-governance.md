# Policy: Data Access and Governance

**Owner:** Information Security
**Last reviewed:** 2026-09-10
**Source:** Internal Confluence — Security Handbook

## Access Levels by Band

| Level | Access scope |
|-------|--------------|
| L1–L3 | Team resources, read-only on shared systems |
| L4–L5 | Team resources plus write access to owned services |
| L6–L7 | Cross-team access on request, approve team changes |
| L8+ | Org-wide visibility, approve budget and access policy |

## Principles

- **Least privilege:** access is granted only for what the role requires.
- **Separation of duties:** the person who requests access cannot approve it.
- **Time-bound access:** elevated permissions expire after 90 days and must be renewed.

## Request Procedure

1. Submit an access request naming the system and business justification.
2. The resource owner reviews within 2 business days.
3. Security logs the grant; access is auto-revoked at expiry.

## Sensitive Data Handling

- Employee PII and financial records are classified **Restricted**.
- Restricted data may not be copied to local machines or external tools.
- All access to Restricted data is logged and audited quarterly.
